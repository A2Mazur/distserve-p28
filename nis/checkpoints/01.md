Выбран независимый уменьшенный CPU-симулятор из задания P28. Подготовлены
авторский эталон и профили закреплённой ревизии, выполнен небольшой пример,
проверены доступность данных для TTFT/TPOT/goodput и аналитический расчёт KV-передачи.

Результат: **18 успешных запусков, 60 завершений запросов, 96 аналитических
сравнений**, максимальная погрешность `5.400124791776761e-13` мс при допуске `1e-8` мс.
Проверены хронология, сохранение запросов и decode-итераций, пустые конечные очереди,
разложение задержки и повторяемость. См. [checks.json](../../artifacts/checkpoint-1/checks.json).

Собственная событийная модель и основные измерительные серии предстоят.

## Технические проверки

### 1. Происхождение и подготовка эталона

Источник: [LLMServe/DistServe](https://github.com/LLMServe/DistServe/tree/82831f1604cc6b10bebd360f6c437a07790dde9f),
ревизия `82831f1604cc6b10bebd360f6c437a07790dde9f`.
Скопированы без изменений только 17 файлов замыкания зависимостей и лицензии;
[manifest](../../third_party/distserve/UPSTREAM.json) фиксирует их SHA-256.
Apache-2.0 сохранена в [LICENSE](../../third_party/distserve/LICENSE).
Ни веса LLM, ни готовые большие workload-датасеты для контрольных случаев не нужны.

Ожидалось: все файлы соответствуют manifest, кластеры запускаются на CPU без GPU.
Получено: все 17 SHA-256 проверены, `DisaggCluster` и `VLLMCluster` отработали
контрольные входы. Зависимости устанавливаются в локальную `.venv`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### 2. Простой случай и эталонный результат

Команда из корня репозитория:

```bash
.venv/bin/python scripts/checkpoint1.py --output artifacts/local/checkpoint-1
```

Конфигурация: [checkpoint-1.json](../../configs/checkpoint-1.json).
Один запрос: прибытие 0 мс, вход 512 токенов, 4 decode-итерации;
OPT-13B, профиль `distserve`, TP=PP=1, без chunking и сети, prefill batch=1.
В обоих вариантах всего два обработчика: 2 общих либо 1 prefill + 1 decode.

Ожидалось: один запрос без очереди совпадает с прямым расчётом по коэффициентам.
Для L=512 prefill вычисляется как `a+bL+cL²+1+2+0.0001L` мс;
каждый decode-шаг k — `a_d+b_d(L+k+1)+c_d+2+0.0001(L+k)` мс.
Первые 1 мс и Ray-overhead учтены так же, как в закреплённом эталоне.
Аналитический расчёт выполнен отдельно, без запуска событийного движка.

Получено в обоих режимах:

| TTFT, мс | Decode, мс | TPOT, мс/токен | Полное время, мс |
|---:|---:|---:|---:|
| 75.1998810534344 | 89.3884719819263 | 22.34711799548158 | 164.5883530353607 |

Свидетельства: [метрики](../../artifacts/checkpoint-1/single-disaggregated-seed7.requests.csv),
[события запроса](../../artifacts/checkpoint-1/single-disaggregated-seed7.events.csv),
[события workers](../../artifacts/checkpoint-1/single-disaggregated-seed7.workers.csv),
[аналитические сравнения](../../artifacts/checkpoint-1/analytical-checks.csv).

### 3. Очереди, повторы и доступность метрик

Той же командой выполняются три изолированных и шесть одновременных запросов,
оба размещения и seeds 7/11/19: всего 18 прогонов и 60 завершений.
Ожидалось: все запросы завершатся ровно один раз, будет нужное число decode-шагов,
время не пойдёт назад, очереди опустеют, метрики будут конечными.
Для изолированных запросов дополнительно ожидалось совпадение с аналитикой.
Получено: все проверки пройдены, 96 сравнений ≤1e-8 мс.

Время для фиксированных входов одинаково при трёх seeds. Это проверка
детерминированности, а не оценка статистического разброса независимых нагрузок.

Данные для главных метрик доступны прямо из лога:
TTFT = первое `wait_decode` − `init`;
TPOT = (`exit_system` − первое `wait_decode`) / число decode-шагов.
В эталоне `output_lens=D` — число decode-итераций, полный выход O=D+1;
CSV сохраняет обе величины. Goodput считаем по числу запросов, одновременно
выполнивших TTFT≤200 и TPOT≤100, делённому на окно от первого прибытия до
последнего завершения. В [summary.csv](../../artifacts/checkpoint-1/summary.csv)
есть окно, throughput, goodput и нормировка на одинаковые два ресурса.
Это короткие контрольные трассы, не итоговое измерение устойчивой производительности.

Независимая повторная проверка сохранённых свидетельств, только стандартная библиотека:

```bash
python3 scripts/verify_evidence.py artifacts/checkpoint-1
```

Ожидалось: SHA-256 совпадут, метрики пересчитаются из событий и совпадут с CSV.
Получено: `PASS`, 18 прогонов, 60 пересчитанных метрик запросов,
96 аналитических сравнений. [Сводка и разбор](../results.md).

### 4. Предпосылки сетевой модели

```bash
.venv/bin/python scripts/network_sanity.py --output artifacts/local/checkpoint-1/network-sanity.json
```

Ожидалось: для OPT-13B, FP16, L=512 объём K+V равен 400 МиБ; удвоение объёма
удваивает время, удвоение bandwidth делит его пополам, единицы Гбит/с и мс
согласованы. Получено: `PASS`, 419430400 байт; при 10 Гбит/с и нулевой
дополнительной задержке — 335.54432 мс на перенос.
Свидетельство: [network-sanity.json](../../artifacts/checkpoint-1/network-sanity.json).
Это арифметическая проверка допущений; событийная сеть с конкуренцией ещё не реализована.

## Ресурсы

Проверено на macOS arm64, Python 3.14.8, CPU, физическая память 16 ГиБ.
Полный контрольный набор после прогрева импортов занял около 0.4 с и около 82 МиБ
пиковой RSS; холодный первый запуск занял около 13 с.
Точные версии и замер: [environment.json](../../artifacts/checkpoint-1/environment.json).
Для этих проверок CPU и памяти достаточно. GPU и платные ресурсы не используются.

Стоимость полных серий пока не измерена: до 23.11 провести пилот и при необходимости
уточнить сетку параметров по [плану](../experiment-plan.md).
